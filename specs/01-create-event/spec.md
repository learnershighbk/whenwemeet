# Spec 01 — Create Event

상태: **Approved** (2026-10-17) · 근거: `docs/prd.md` §3-1, 원본 PRD F-1~F-5

## 1. 범위
`/` 페이지의 첫 단계(`form`). 회의명·날짜·시간대·타임존을 입력하고 `Create Event`를 누르면 다음 단계(`edit`, Spec 02)로 넘어간다.
- 포함: 입력 폼, 검증, 단계 전환 시 넘길 데이터(`EventDraft`)
- 제외: 그리드 표시·편집·저장 (Spec 02). 이 단계에서는 서버에 아무것도 저장하지 않는다.

## 2. 화면

```
Plan a meeting
┌───────────────────────────────────────┐
│ Event name  [e.g. Weekly team sync  ] │
├───────────────────────────────────────┤
│ Which days?            ( ) Date range │
│   ‹  October 2026  ›                  │
│   Su Mo Tu We Th Fr Sa                │
│   ...  [20][21] 22 ...                │
│   5 days selected                     │
├───────────────────────────────────────┤
│ What times?                           │
│   From [10:00 AM ▾]  To [4:00 PM ▾]   │
│   Time zone [Asia / Seoul (GMT+9) ▾]  │
├───────────────────────────────────────┤
│            [ Create Event ]           │
└───────────────────────────────────────┘
```
- 데스크톱: 위 순서 그대로 한 열, 최대 폭 약 640px로 가운데 정렬.
- 모바일: 같은 순서, 좌우 여백 16px, 버튼은 전체 폭.

## 3. 요구사항

### R1. 회의명
- 필수. 앞뒤 공백 제거 후 1~100자. 100자 넘게 입력되지 않음.

### R2. 날짜 — 캘린더
- 월 단위 캘린더, `‹` `›`로 이동. 처음에는 이번 달 표시.
- 오늘 이전 날짜는 흐리게 표시하고 클릭 불가. 이번 달보다 이전 달로는 이동 불가.
- 선택한 날짜는 검정 배경 + 흰 글자. 오늘 날짜는 밑줄 등으로 구분.
- 선택 개수 표시: `1 day selected` / `{n} days selected`. 0개면 표시 없음.

### R3. 날짜 — 두 가지 모드
- **Pick dates (기본)**: 클릭할 때마다 선택/해제. 여러 달에 걸쳐 선택 가능.
- **Date range**: `Date range` 토글을 켜면 전환.
  - 첫 클릭 = 시작일, 두 번째 클릭 = 종료일 → 사이 모든 날짜 선택.
  - 두 번째 클릭이 시작일보다 앞이면 두 날짜를 바꿔서 적용.
  - 범위가 정해진 뒤 다시 클릭하면 새 범위의 시작일로 처리.
  - 시작일만 고른 상태에서는 그 날짜 1개가 선택된 것으로 본다. 선택 개수 옆에 `· Now pick the last day.` 안내를 붙인다. *(구현 중 추가)*
- 모드를 바꾸면 선택한 날짜를 모두 지운다.
- 최대 31일. 초과하는 클릭/범위는 적용하지 않고 `You can pick up to 31 days.` 표시.

### R4. 시간대
- From 선택지: `12:00 AM` ~ `11:00 PM` (1시간 간격, 24개)
- To 선택지: `1:00 AM` ~ `12:00 AM` (마지막은 자정 = 24시, 24개)
- 기본값: From `10:00 AM`, To `4:00 PM`
- From을 To와 같거나 이후로 바꾸면 To를 From + 1시간으로 자동 변경.
- To 목록에서 From 이하인 시간은 비활성화.

### R5. 타임존
- 기본값: 브라우저 타임존 (`Intl.DateTimeFormat().resolvedOptions().timeZone`).
- 목록: `Intl.supportedValuesOf('timeZone')`를 대륙(첫 `/` 앞)별로 그룹화. 그룹 순서는 알파벳순.
- 표시 형식: `Asia / Seoul (GMT+9)` — 도시 이름의 `_`는 공백으로, GMT 오프셋은 오늘 기준.
- 입력해서 걸러 보는 검색 기능 제공 (도시·대륙 이름 부분 일치, 대소문자 무시).
- 브라우저 타임존이 목록에 없으면 `UTC`를 기본값으로 사용.

### R6. Create Event
- 회의명이 있고, 날짜가 1개 이상일 때만 활성화. 비활성 시 버튼 회색.
- 클릭하면 `EventDraft`를 만들어 `edit` 단계로 넘긴다:
  ```ts
  type EventDraft = {
    title: string          // trim 된 값
    dates: string[]        // 'YYYY-MM-DD', 오름차순
    startHour: number      // 0–23
    endHour: number        // 1–24
    timezone: string       // IANA
  }
  ```
- `edit` 단계에서 `Back`으로 돌아오면 입력값이 그대로 남아 있어야 한다 (모드 포함).

## 4. 수용 기준 (AC)

| # | 기준 | 확인 방법 |
|---|---|---|
| AC1 | 처음 열면 From 10:00 AM, To 4:00 PM, 타임존은 브라우저 타임존 | 수동 |
| AC2 | 날짜를 클릭하면 선택, 다시 클릭하면 해제. 개수가 맞게 표시됨 | 수동 |
| AC3 | Date range에서 10/24 → 10/20 순서로 클릭하면 10/20~10/24 (5일) 선택 | 단위 테스트 + 수동 |
| AC4 | 모드 전환 시 선택이 초기화됨 | 수동 |

| AC6 | 32번째 날짜는 선택되지 않고 안내 문구가 보임 (두 모드 모두) | 단위 테스트 + 수동 |
| AC7 | From을 4:00 PM으로 바꾸면 To가 5:00 PM으로 바뀜. To 목록 마지막은 12:00 AM | 단위 테스트 + 수동 |

## 5. 구현 메모
- 날짜 계산(범위 펼치기, 31일 제한, 시간 라벨, To 자동 조정)은 `src/lib/dates.ts` 순수 함수로 작성하고 테스트한다.
- 컴포넌트: `Calendar`, `TimezoneSelect` (`src/components`). 단계 상태는 `CreatePage`가 관리.
- 이 Spec 범위에서는 Supabase 호출 없음.
